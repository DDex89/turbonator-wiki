'95 Neon FCC: fault codes

Generated by tools/gen_fault_docs.py from the fault descriptors at $D4E3 (160 entries of 8 bytes, index × 8 + $D4E3). Do not edit by hand.

See also error code masking (SMEC/SBEC) and tuning notes.

Descriptor layout

Byte
+0 Fault index (0-159)
+1 Maturing count: how many failed tests before the fault is stored (1 = at once)
+2 Chrysler flash code, BCD
+3 Flags, see below
+4, +5 Bit mask and byte offset of the fault bit in the bitmap at $0135
+6, +7 OBD-II code in BCD, for example 01 22 = P0122; 00 00 = none

Flags (byte +3)

Bit
7 Fault enabled. When clear, ThrowNonCriticalError returns without storing anything [code]
6 Emission related: counted in $010D (number of OBD-II codes) and captures a freeze frame [code]
5 Sets $0070 bit 7, which the lamp logic (CheckIfCheckEngineLightShouldBeOn_A_MM) reads. Set only on charging-system faults, so probably the charge indicator lamp [inferred]
4 Always go through the maturing counter [code]
3 Store at once, without the maturing counter [code]
0-2 Freeze frame priority: a higher value overwrites a stored frame [code]

How faults are stored

ThrowNonCriticalError ($5B0A) takes the descriptor address in Y. A fault that is not stored at once uses one of two maturing slots ($0054/$0055, counters at $0056/$0057) and is stored when the counter reaches byte +1. A stored fault sets its bit in the bitmap at $0135 and is pushed into the list of the last eight stored faults at $001B-$0022 (most recent at $0022), which the DRB reads with command $10. The key-on counters at $0023-$0025 age old codes out.

An emission-related fault also captures a freeze frame at $011E-$0126 (CaptureFreezeFrame, $EC86): fault index, load, coolant, short-term and adaptive fuel trim, RPM, vehicle speed and two more values. LECD7 later compares the current RPM and MAP with the frame (the OBD-II “similar conditions” check). Together with the ISO 9141 routines this means the 1995 FCC already carries most of the OBD-II machinery.

Checksum (code 53). In both images descriptor 2, which CaculateChecksum reports, has the enable bit clear, so a checksum mismatch is not stored at all. In the factory B559 images (table at $D4E9) it is enabled, so keep fixing the sum after edits.

Differences between the images

  • $D96B (#145): 91 01 14 13 02 13 12 99 → 91 01 14 d3 02 13 12 99 (5269718 → 5007033)
