    How to flash the Neon FCC using the FCCFlash Tool.

    Overview

    Flashing the '95 Neon FCC with the FCCFlash Tool.

    The original FCCFlash instructions are reproduced and reorganized below. They describe the FCCFlash Windows utility and its matching USB flashing adapter with the red boot button.

    Set up the USB-to-SCI cable (Windows)

    Follow Setup the USB to SCI cable in the original Turbonator Wiki. In brief:

    1. Connect the USB-to-SCI cable to the Windows PC and allow the driver to install.
    2. Open Device Manager, find the FTDI USB device and open its properties.
    3. Enable Load VCP Driver on the Advanced tab (see the original wiki screenshots).
    4. Disconnect and reconnect the cable. Windows should enumerate it as a COM port.
    5. Start FCCFlash and confirm its status bar shows the assigned COM port.

    If the COM port does not appear, the original cable setup guide discusses reinstalling an FTDI driver; the archived download URL may no longer work. A non-BoostButton cable may also require FTDI EEPROM configuration and protection against the 12 V present on SCI during flashing. Those advanced modifications are not the same as simply enabling VCP in Windows. Do not assume that an ordinary USB-TTL cable is safe to use.

    Flash the calibration with FCCFlash

    1. Connect the FCCFlash adapter to the vehicle diagnostic port and to a USB port on the PC.
    2. Start FCCFlash, and verify that the status bar shows the adapter's COM port.
    3. Click Button #1 (Boot the FCC). The popup describes a short key-on window (reported as around five seconds, but not confirmed in the original instructions).
    4. Press and hold the red button on the flashing adapter.
    5. Turn the ignition ON and immediately release the red button (approximately 0.5 seconds after key-on).
    6. A successful boot disables Button #1 and enables Buttons #2, #3 and #4.
    7. Optional: Click Button #2 to read and save the existing calibration.
    8. Click Flash. FCCFlash identifies the ECU, then erases the calibration; a file selection dialog opens afterward.
    9. Select the compatible .bin file when prompted.
    10. Allow roughly three minutes for programming. The version described by the original author does not show a progress indicator. Do not disconnect the adapter or turn off the ignition while programming is in progress.

    Troubleshooting and limitations

    • ECU identification or erase may occasionally fail. The original author reported that restarting the flashing procedure often worked on a second attempt.
    • Recommended RTS and programming timeout settings were not provided in the original instructions.
    • Preserve a verified copy of the original calibration where possible; verify ECU, code-base and binary compatibility before erasing.
    • The source describes a calibration flash. It does not establish that FCCFlash can program arbitrary complete ROM images.
    • The procedure above is for the FCC, not the SBEC3/SCI bootloader procedure described in SBEC3 reflash.

    Background: what the FCC expects from a flash

    This section is reverse-engineered from the firmware itself (see FCC overview and calibration), not from the FCCFlash tool's own documentation, so treat it as “how to tell whether a download is sane” rather than tool instructions.

    • Checksum. The controller sums every byte of the EPROM image, 8-bit, wrapping; the result

    must equal the byte at $B805 (the last byte of the BCD part number). If it doesn't, the FCC 

      won't run on it. Any chip burner or MP Tune-compatible tool fixes this automatically when it
  writes a calibration change, but if you build or edit a ''.bin'' by hand, re-check or re-sum it
  before burning.
* **Code base must match.** The calibration (roughly ''$B800''-''$E228'') can be swapped freely
  between two images **only if they share the same code base** — the program code outside the
  calibration area has to be byte-identical, because the fixed addresses the code reads
  (''LDX #table'', ''CMPA $xxxx'') assume the calibration layout of that one code base. See
  [[fcc_calibration#all_images|the code base table]] for which part numbers go together (B559,
  B4F3, B4C2, B4CC, ...). Flashing a calibration from one code base onto a chip built for another
  will boot into garbage at best.
* **Byte-mode download over the diagnostic line.** The FCC's own DRB-protocol serial link (pins 9
  RX / 30 TX, see [[fcc_sci|diagnostics and communication]]) has a command, ''$1B''
  (''InitByteModeDownload''), that puts the controller into a byte-mode code download over that
  same line. This is the path a DRB-class tool (and, most likely, FCCFlash) uses to get bytes
  into the chip without pulling it from the socket; it's a different mechanism from EPROM
  chip burning (see [[chip_burning_basics|chip burning basics]]) and from [[ecu_socketing|ECU
  socketing]] for in-circuit reprogramming.
* **EPROM size.** The program fills the full ''$1200-$FFFF'' window (60,928 bytes) of a 27C512 or
  equivalent; make sure whatever you flash is exactly that size and not truncated or padded
  wrong.
